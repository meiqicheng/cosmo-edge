# 持续补充用例

唯一维护入口是 `test/customer-journey/CosmoEdge-客户旅程测试用例.xlsx`。原 v0.1 为历史评审稿；正式主库保留其用例编号和覆盖表，并增加执行必需字段。`suite.json` 自动生成，仅用于 GitHub 查看文字差异。`coverage.json` 是早期源码盘点参考，不能代替工作簿更新。

主要功能快测维护入口是 `test/customer-journey/CosmoEdge-主要功能客户旅程测试用例.xlsx`；`quick-suite.json` 是它的生成镜像。新增快测用例继续使用未占用的 Q 编号，补全“主要用例”的资源、全量来源映射、预计耗时与清理，以及“步骤与验收”的逐步操作、预期、证据。保留历史编号，更新“评审总览”A3 的版本。执行结果只写每轮 run，不写回用例库。变更后对该工作簿执行 `compile --workbook ... --output test/customer-journey/quick-suite.json` 与相同参数加 `--check`，并运行快测集成测试。

保留 sheet 名及第 4 行列名，数据从第 5 行开始。定义字段使用普通文字，编译器不执行公式。总览的统计公式允许保留。“文档类型”必须为“用例库”；结果工作簿不能作为主库输入。

- **详细用例**：在 Excel 表格末尾新增行，取模块下未使用编号，例如 FACE-015。填写标题、旅程、模块、P0/P1/P2、前置、操作步骤、预期、清理、适用边界、来源、执行方式、回归层级；T 列“修订”填正整数，U 列“资源编号”用分号分隔，V 列“执行器”按相近用例填写。步骤每行一个动作，生成 S01、S02 等编号；预期生成 A01。
- **资源与缺口**：登记通用资源 ID、名称、类型、准备要求和必填字段。实际地址/账号/密码/素材路径放在 ignored 私有配置中，用 ID 绑定。
- **设备矩阵**：每行实例 ID 与“关联用例”生成独立检查；多个用例用分号分隔。
- **参数覆盖**：每行 PAR 编号及“关联用例”生成参数检查，包含默认值、约束、依赖和语义。
- **组件覆盖**：目录和组件 ID 共同形成检查编号；“关联用例”决定归属。
- **接口覆盖**：每行 APIREF 编号分别为 API-001/002 生成认证和契约检查。“业务用例”供导航，具体业务步骤仍维护在详细用例。
- **补充检查**：填写用例 ID、自定义检查 ID（字母/数字/横线/下划线）和可判定内容，生成 EXTRA 检查。禁止重复编号或引用不存在的用例。
- **客户旅程 / 功能覆盖 / 算法覆盖**：评审导航与覆盖参考；新增功能需同步这些表及对应可执行用例。

新增/修改后递增总览“用例库版本”（语义版本，如 1.2.0）；修改既有用例时递增其修订。原编号不复用。Excel 新行需扩展表格和总览范围；结果导出会按实际行重建计数。不要在主库填写本轮结果；主库结果列保持未执行和空白。

每轮独立保存工作簿和 JSON 快照。变更主库不会改变历史 run；不可编辑历史快照以声称旧结果覆盖新增检查。

校验：

```text
python tools/customer_journey.py compile
python tools/customer_journey.py compile --check
python tools/customer_journey.py validate
python -m unittest discover -s test/customer-journey -p "test_*.py"
npm run docs:verify
```

提交工作簿、生成的 `suite.json`、相关技能和工具修改。不可提交私有配置、个人素材、设备抓图及运行报告。同步仓库内 `skill/` 到本机 `.agents/skills/cosmoedge-full-test/` 后，检查安装副本与源文件一致。

库校验成功证明结构可用，不证明新增用例已经在设备上通过。新用例下一轮初始状态必须是未执行。
