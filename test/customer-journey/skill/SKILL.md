# CosmoEdge 逐用例全量与主要功能快测

目标：用户一句“对 CosmoEdge <IP> 用户名 <账号> 密码 <密码> 做全量测试”，即可由 Codex 调度用例库，逐条执行、保存进度并给出清楚的通过/未通过原因。这里的执行者是 Codex 及可用浏览器/API工具；`customer_journey.py` 管理队列、校验记录、生成报告，不会自己点击网页。

在 CosmoEdge 仓库工作，先读其 AGENTS.md。全量用例源是 `test/customer-journey/CosmoEdge-客户旅程测试用例.xlsx`，主要功能快测用例源是 `test/customer-journey/CosmoEdge-主要功能客户旅程测试用例.xlsx`；`suite.json` 和 `quick-suite.json` 仅为自动生成的 Git 审阅副本。按用户措辞选择相应 XLSX，不能用快测结果回填全量用例。优先读取 `COSMO_JOURNEY_RESOURCE_ROOT` 或 ignored 的 `output/agent-runs/cosmoedge-test-kit/resource-root.local.json` 所指向的私有资源包；未配置根目录时才使用 `output/agent-runs/cosmoedge-test-kit/resources.private.json`。启动前检查资源缺口，换机首次检查包含文件哈希。流程详见 [references/execution.md](references/execution.md)，添加用例详见 [references/maintenance.md](references/maintenance.md)。

## 入口和准备

1. 从用户输入读取本轮目标，复制默认资源配置到新的私有 run；覆盖 `resources.DUT` 的地址和登录凭据。不能沿用精度脚本内置目标，也不能把旧版本的算法数字 ID 当作新版本必然存在。
2. 在仓库根目录运行 `python tools/agent_workflow.py start` 创建本轮合同和评估。用户明确请求的实机测试、既有精度服务器访问范围按会话授权记录，不重复询问。需要 SSH 时使用 `python tools/remote_access.py --contract <本轮合同> --host <主机> --user <用户名>`，通过交互提示输入密码。
3. 全量使用默认 `python tools/customer_journey.py init --run <run> --profile <本轮私有配置>`；快测加 `--suite test/customer-journey/CosmoEdge-主要功能客户旅程测试用例.xlsx`。两者都校验 XLSX 并冻结工作簿及执行清单，随后运行 `preflight --run <run>`。配置文件明文凭据只有用户明确允许时才保存，且只保存在 ignored 私有路径；报告和通用库不得包含凭据。
4. 一次性汇总缺少的资源/适用授权；先检查能由 Codex 自己读取、导出、生成或探测的内容。用户无需重新提供已配置的账号和素材。缺资源只阻塞依赖它的用例，继续所有独立用例。

## 执行循环

- 调用 `next --run <run> --limit 1`，读取该条全部步骤、断言、资源引用、适用性和清理要求。按顺序完成这一条，再处理下一条。共享准备对象可复用，但各厂商/通道/参数/API的结果分别记录。
- 使用当前会话指定的浏览器工具实际完成页面操作；浏览器观察和控制遵守该工具协议。接口/脚本只用于用例指定的接口测试、精度压力任务及交叉验证。不得把HTTP 200、页面打开或上传成功当作业务闭环通过。
- 普通可恢复UI增删改在测试请求范围内执行，临时对象统一 `QA_<run>_`。先盘点现有对象，只清理本轮创建的对象；清理结果也留证。不要关闭用户现有任务以掩盖资源不足。
- 每条用例用 `template` 生成结果输入，实测后用 `record` 提交。每个已测步骤/断言记录观察与证据。工具拒绝缺步骤、缺断言、缺证据或未核对清理的通过状态；每次提交自动更新报告。
- `FAIL` 指预期与实际不符，必须指出失败步骤；`BLOCKED` 指具体资源、配置或授权缺失；`PARTIAL` 是已做部分且仍有未完成项；`NOT_APPLICABLE` 需要部署能力证据。未开始用例保持 `NOT_EXECUTED`，不得改成阻塞来充数。
- 每项未通过结论必须带原因分析：已证实事实、尚未完成的具体检查、下一步动作、处理方及证据。历史记录没写停止原因时明确 UNKNOWN，不能用“资源不足”补造原因。使用 `explain` 补充分析，不修改原状态或冒充重新实测；最终报告检查 `unexplainedCases` 和 `unknownCauseCases`，不能只报数量。
- 资源依赖按实际步骤核对。某厂商异常不阻塞其他厂商；页面校验不自动依赖硬件闭环；本地构建、重启/出厂不能统一等待升级包。聚合用例按动作/参数/样本形成独立结果。发现原用例范围或资源绑定错误，单列待修订项，不能据此跳过可执行步骤。
- 全量库的参数、组件、接口和设备矩阵作为子断言绑定到全量用例。不能用测一个参数替代581参数，测一台海康替代另一台。快测只按其 Q 编号和明确抽样范围验收，不产生全量矩阵通过结论。明确不适用的子断言可记 `NOT_APPLICABLE` 并附能力证据。
- 精度/稳定性脚本要等待真实完成。记录解码/推理就绪、样本真值、错误分母及原始首轮结果；重试作为新尝试保留。不得把600个视频样本计作600条功能用例。24小时用例未跑足时长就不能通过。
- UI失败先观察阻塞原因再有限重试。连续两次同因失败保留证据，记录失败或工具阻塞并继续独立用例；不要无限重试或默默跳过。长任务使用可轮询进程及落盘状态，定期向用户简报。

## 权限与可完成边界

全量或快测请求授权普通测试流程，不会绕过平台工具的实际审批。密码变更需用户接管；网络改址、恢复出厂、断电、升级等必须有适用授权与可用恢复条件；缺失时具体标记阻塞并继续其他用例。涉及人员图片/信息的外发需已有明确数据和目的地授权；被自动审批拒绝后不得换工具绕过。

不能因为用户用一句话要求测试就声称所有步骤可无人值守，也不能只因存在这些步骤而停掉可执行的其他用例。

## 结束与恢复

继续至所有可执行用例有结论；不能因运行时间较长或报告已生成就提前宣告完成。中断后读取同一run继续，不重置结果。已阻塞项目在资源补齐后显式重测指定ID；`next` 默认只返回未执行/部分完成项。

核对临时对象清单、原配置、原任务和接收辅助进程；恢复浏览器视口。运行 `report --run <run>`，同时生成逐用例结果 XLSX 和 HTML，给用户两份报告及各状态数量。结果 XLSX 按编号回填冻结副本，保留主库；全量报告的“步骤与检查结果”和快测报告的“步骤与验收”记录细项，重测历史在持久化结果与 HTML 中保留。没有全量实测证据时，直说未完成全量验收。旧版记录导入不等于按新版工作簿重测。

## 维护

用户要求新增用例或已发现可复现缺陷时，编辑相应的正式 XLSX，追加稳定编号并更新版本，再运行 `compile` 生成审阅 JSON。保留原有编号和历史 run 快照。新用例必须有可操作步骤、可判定预期、资源引用和恢复方法，不能只写“功能正常”。运行 `compile --check`、校验与原生单元测试；对新用例未实机跑过的事实如实说明。
